# MegaD: совместимость с современным Home Assistant

Форк [andvikt/mega_hacs](https://github.com/andvikt/mega_hacs) для MegaD-2561 и MegaD-328. Исправления основаны на стабильной версии **1.1.7**.

Цель: сохранить существующие устройства, `entity_id`, `unique_id`, события и автоматизации при обновлении Home Assistant. Домен интеграции остаётся `mega`; настройки контроллеров и идентификаторы портов не меняются.

## Совместимость

Релиз **1.1.7.post20261018** проверен при работе с Home Assistant Core **2024.12.1**, **2025.7.4** и **2026.10.2**. Проверка загрузки и сохранения идентификаторов не означает испытание всех моделей контроллеров и подключённых устройств. Совместимость с будущими версиями HA заранее не гарантируется.

## Установка через HACS

1. Сделайте полную резервную копию Home Assistant и сохраните её вне Raspberry Pi.
2. В HACS откройте меню → «Пользовательские репозитории».
3. Добавьте `https://github.com/MazurenkoEvgeniy/mega_hacs`, категория **Интеграция**.
4. Скачайте релиз из этого форка и перезапустите Home Assistant.

**При переходе с другого репозитория не удаляйте Mega из «Настройки → Устройства и службы».** Там хранятся действующие записи контроллеров. Сначала сделайте копию `custom_components/mega` и убедитесь, что HACS устанавливает файлы именно этого форка. Не устанавливайте два разных варианта домена `mega` одновременно. После перехода проверьте идентификаторы, входы, свет и автоматизации.

При ручной установке заменяется только папка `custom_components/mega` из релиза. Конфигурация и реестры HA не удаляются.

## Что исправлено

- Удалён вызов `bind_hass`; привязка сервисов к HA сохранена.
- Обновлены загрузка/выгрузка платформ и обработчик настроек.
- Заменены удалённые константы единиц измерения и возможностей света.
- Используется работающий цикл asyncio; координатор получает запись интеграции.
- Конфигурация обновляется через API HA, а не присваиванием `ConfigEntry.data`.
- До платформ создаётся родительское устройство контроллера; существующие устройства портов сохраняются.

Команды контроллерам, обработка входов и расчёты датчиков в этом релизе не перерабатывались.

## Будущие обновления

Не нажимайте «Sync fork» без проверки изменений: это может вернуть несовместимые файлы upstream. Перед выпуском новой версии проверяйте изменения API HA, загрузку интеграции, сохранение идентификаторов и работу устройств на тестовой установке. Затем увеличивайте версию в `manifest.json`, публикуйте соответствующий GitHub Release и проверяйте его установку через HACS.

Известно предупреждение HA 2026.10 о старом параметре `via_device`: оно не блокирует текущую работу, но требует отдельной миграции до HA 2027.8 с проверкой сохранения связей устройств.
